## 起因

先对整个项目做了一次从第一性原理出发的对抗式审查（不改代码，只找问题），按 P0/P1/P2 分级，然后把所有条目按顺序改完。

审查的结论大意是：**功能是能用的，但很多地方是「看起来对」而不是「真的对」** —— 安全边界靠默认值、密钥明文躺在那、文档写的内容和代码不是一回事、错误路径基本没考虑过。

## 改了什么

### 1. 安全边界（P0）

- `nodeIntegration` 关掉、`contextIsolation` 打开，渲染进程不再有 Node 能力；界面唯一能调的东西是 `preload.js` 里显式列出的那几个通道。
- `index.html` 加 CSP：`script-src 'self'`、`connect-src 'none'`、`object-src/base-uri/form-action 'none'`。渲染进程发不出网络请求，模型输出也带不进脚本。
- `scripts/markdown.js`：marked 默认把 Markdown 里的原始 HTML 原样透传，现在加自定义 renderer 把 HTML 转义；链接只放行 `http(s)`/`mailto`，图片只放行 `https:`，`javascript:` 之类的降级成 `#`。
- `scripts/window-guards.js`（新）：拦 `window.open`、拦窗口内导航、拦 `<webview>` 附着，外部链接交系统浏览器。顺带把菜单被去掉后失效的 accelerator 用 `before-input-event` 补回来（F12 / Ctrl+Shift+I / Ctrl+Q）。

### 2. 密钥与配置可靠性（P0/P1）

- `apiKey` / `notionToken` 经 `safeStorage`（Windows DPAPI）加密成 `enc:v1:...` 再落盘；跨 IPC 只给 `hasApiKey` / `hasNotionToken` 两个布尔。
- 写盘改成 `tmp` + `rename` 原子替换。
- 读配置失败分成三种情况分别报：文件损坏 / 密钥解不开（换机器或换 Windows 账户）/ 系统密钥库不可用。以前这些会被统一伪装成「还没配置」，人只会以为是自己没填。
- `migrateStore()` 兼容老字段（`deepseekApiKey`）和明文密钥，改字段名不会让谁重填。

### 3. Notion 归档保真（P0/P1）

- 重写 Markdown → Notion 块：表格（含 `table_row` 单元格数对齐）、待办、折叠块、代码（带 language）、引用、分割线、行内加粗/斜体/删除线/行内码。（这条日志当时还写了「图片」和「下划线」，2026-10-02 核对代码：行内图片是**退化成链接**而不是转成 image 块，`<u>` 下划线从来没有实现过，已从需求文档删掉。）
- 数据库属性先 `GET` 探测再写：库里没 `Date` 就跳过，不再固定往不存在的属性上写导致 400。（这条日志当时顺手写了「没 `Date`/`Tags` 就跳过」，但代码里**从来没有写 `Tags`**，2026-10-02 核对 README 时才发现，需求文档已按实际行为改正。）
- 分批：单次 ≤100 顶层块、单段 rich_text ≤2000 字符，超出走 append。
- 日期用本地当天，不是 UTC（以前晚上生成的笔记会跑到明天）。

### 4. 交互与反馈（P1/P2）

- **中止生成**：主按钮生成中变「中止」，按 requestId 掐掉还在飞的三个请求，已经回来的那一版保留。
- **部分失败可见**：哪一档没生成出来，标签上留红点 + `title`，切过去看完整错误，同时 toast 点名「笔记版没生成出来：…」。
- **弹窗关闭条件**：没配齐时取消/遮罩/Esc 都不让关，并说清还差哪几项；配齐后自由关。
- **键盘**：分段控件按 radiogroup 契约实现（roving tabindex + 左右/Home/End），全局 `:focus-visible` 描边。
- **对比度**：文字灰阶整体调深（`#86868B` 3.3:1 → muted 6.8:1 / faint 4.5:1），强调绿从 `#248A3D` 加深到 `#1F7A35` 才能当正文色用。

### 5. 笔记不再易失（P2）

## 怎么验的

没有测试框架，用临时 Electron 探针：`electron.exe --user-data-dir=$TEMP/xxx .probe-stepN.js` 起隐藏窗口跑真实 `index.html` + 真实 `preload.js`，本地 mock HTTP 服务当模型接口和 Notion，结果写 `.probe-stepN.json` 再读（不用管道，Windows GUI 子系统的 stdout 不接管道会挂死）。

今天实际跑过的：

- **Step 1** 安全边界：`window.require` / `process` 在渲染进程取不到；`<img onerror>` 之类的注入被转义；`javascript:` 链接不成链；`window.open` 被拒且 URL 交给注入的 `openExternal`；`location.href` 导航被 `preventDefault`；F12/Ctrl+Shift+I 开关控制台；Ctrl+Q 真退出。
- **Step 2** 配置：明文密钥自动升级成 `enc:v1:`；换机器解不开时报的是「密钥解不开…请重新填写」而不是「还没配置」；写坏 JSON 能报「文件损坏」；重启不丢配置。
- **Step 3** Notion：假服务收 payload，逐块校验类型合法性、`rich_text` 长度 ≤2000、表格单元格数与 `table_width` 一致、120 条列表 + 60 行表格分批送达、日期是本地当天；换库 ID 不吃上一个库的属性缓存。
- **Step 4** 交互：首次启动弹窗关不掉并提示「还差 API Key…」；只填 Key/模型/地址即可生成（Notion 留空）；三档中一档失败 → 红点 + toast 点名 + 切过去看详情；中止后按钮文案恢复、已到的一版保留、mock 服务记录到连接被提前掐断；Tab 顺序与箭头换档实测；截图确认「保存/取消」在折叠线之上。
- **Step 5** 落盘与复制：三版各生成一个文件、名字形如 `2026-10-01 20-28-10 学习版 图结构 A B C D E F G.md`（主题里的 `< > : / * ? " |` 全被换掉）、内容与接口返回一致；复制按钮给的是**当前这一档**的全文（切到专业版后再复制，剪贴板跟着变）；把 notes 目录换成普通文件模拟写盘失败 → 笔记照常显示、toast 是人话且不含路径；`console_errors: []`。

## 之后又改的几处（同一天的界面回环）

1. **气泡盖住结果区按钮**：`.toast` 贴在 `bottom:20px`，结果区打开时正好压住「复制 Markdown / 保存到 Notion」。用 `body:has(.result--active) .toast { bottom: calc(var(--space-lg) + 48px) }` 抬上去，命中测试确认两个按钮都能点。
2. **配置窗底部漏缝**：`position:sticky` 贴的是滚动容器的**内容盒**底边，`.config-modal` 自己的 `padding-bottom:20px` 在吸附条下面留了一条没人盖的缝，滚过去的字段从缝里露半行字。留白改由吸附条自己的 padding 出。
3. **吸附条上沿压在按钮头顶**：上一条只补了 `padding-bottom`，结果不透明带的上边正好切在按钮顶上，看着像按钮被削掉一截（他截图里指的就是这个）。补 `padding-top: var(--space-md)`，并在**真吸附状态**（滚动条停在中间）下量 `条.top → 按钮.top = 12px`、`按钮.bottom → 窗底 = 12px`、缝隙 0。
4. **本机笔记自动存盘改成开关**：配置窗「本机笔记」里加 `生成后自动存到本机`（`autoSaveNotes`），关掉后 `notes:generate` 不写文件也不建 `notes` 目录，说明文字跟着换；配置文件里没这个字段的老版本按「开」读，行为不变。顺带把「本机笔记」那个 `<label for="btn-open-notes">` 的 `for` 去掉——点标题等于点「打开文件夹」会直接弹资源管理器。
   探针跑过：缺字段时 `boot.config.autoSaveNotes === true`；开关 42×26、焦点可达、空格能切；关掉后保存 → 配置文件里 `autoSaveNotes: false` 且 `apiKey` 仍是 `enc:v1:`；关着生成 → 接口照样收到 3 个请求、结果正常显示、`notes` 目录**没有被创建**；重开配置窗记住是关着的 → 打开再生成 → 三个文件名字和内容都对；`console_errors: []`。
   **写这个功能时自己踩了一个真 bug**：`NOTES_HINTS` 声明在文件后半段，而首次启动的 `showConfigModal()` 在前面就调了 `syncNotesHint()` → const 还在 TDZ 里 → 整个 `DOMContentLoaded` 抛错、配置窗不出现。是探针里「所有 rect 都是 0 + 保存后配置文件不存在」暴露的，已把声明挪到 DOM 引用区，并写进 `CLAUDE.md` 的编码约定。
5. **接上一条的两处修改（他随后提的，第 4 条里「老配置按开读」已被这条推翻）**：
   - **自动存盘默认改成关**。原来是 `data.autoSaveNotes !== false`（缺字段＝开），现在 `data.autoSaveNotes === true`（缺字段＝关）。理由是写盘是副作用，不该默认往人硬盘上放东西；代价是已经用过的人升级后不再自动写文件，需要在配置窗里自己打开——这是明确要求的行为变更，不是迁移漏了。
   - **笔记目录改成可自定义**。`notes-store.js` 拆成 `defaultNotesDir()` / `normalizeNotesDir()` / `resolveNotesDir()` / `ensureNotesDir()`；配置里加 `notesDir`，`boot:get` 额外返回 `defaultNotesDir` 只给输入框当 placeholder（「留空 = C:\Users\…\notes」，把默认值摊开而不是藏在代码里）。
   - 路径校验放在主进程 `setConfig()` 里：只收盘符开头或 UNC 的完整路径，相对路径当场报错、配置窗不关、配置不写坏；`getConfig()` 读到脏路径当没填（回默认目录），不让一个手改坏的配置文件把生成功能带崩。
   - 新增 `notes:pick-dir` 通道走 `dialog.showOpenDialog({properties:['openDirectory','createDirectory']})`，preload 白名单里加 `pickNotesDir`。
   - 探针跑过：全新配置（无 `autoSaveNotes`/`notesDir` 字段）→ `boot.config.autoSaveNotes === false`、开关渲染为关；填 `…\dl-自定义笔记\notes here`（非 ASCII + 空格）→ 生成三次**三个文件都在自定义目录**，默认 `notes` 目录**全程没被创建**；重开配置窗路径还在；填相对路径 → 报「笔记文件夹要填完整路径，比如 D:\笔记」且弹窗没关、配置文件没变；清空路径 → 回到默认目录；`boot.notesDir` 跟随配置；本机笔记整块 `top:348 bottom:532`，吸附条 `top:552`，滚进视口不被压住；两个按钮 `elementFromPoint` 命中；`console_errors: []`。
   - **没点过的**：「自定义保存位置」（原名「选文件夹」）和「打开文件夹」都会弹系统原生对话框，探针里只断言 `typeof window.dl.pickNotesDir === 'function'`，没有真点。
6. **按钮文案「选文件夹」→「自定义保存位置」**（他截图圈出来直接改的）。探针复量：文案生效、与「打开文件夹」同一行（两者 `top` 相同、高度都是 39，和「拉取最新」这个同款 mini 按钮等高 → 没折行）、`scrollWidth <= clientWidth`（没截字）、行右沿距弹窗内边 29px（没溢出）、`scrollIntoView` 后 `elementFromPoint` 命中按钮本身、`console_errors: []`。
